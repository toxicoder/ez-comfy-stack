Opt-in, never a service

The lane ships inside the Comfy pack (custom_nodes/ez_edit/) as routes plus one sidebar panel. The agent brain is the opposite: an opt-in host process you start yourself. It is not a Compose service, not cloned into docker/Dockerfile, not pinned in any promoted graph, and it never changes restart: "no", the heavy confirm, or the headroom

Server or client render

The two modes are not quality settings; they decide which machine decodes, composites, and encodes, and therefore which container you get.

ffmpeg runs on the Spark from the same argv the pack builds for the project (concat, cut, trim, fade, wipe, per-clip volume). Text overlays and captions are not burned in this pass - the row appends ; 2 text planes render in client mode and the video plus audio still render. Stop Comfy first (./scripts/manage.sh stop) if the encode is long enough to matter; it is a CPU job, but the box is one box. A row that fails with ffmpeg not found on PATH means the binary is missing in the container: install it there, or use client mode.

Etiquette, in the order that avoids a refuse:

  1. Chat and edit first, generate last. Tool calls and trims are free; a cutaway is a Wan print.
  2. Release the desk before you generate - bazelisk run //:manage -- occupancy enter idle, then Send the generate request.
  3. One cutaway at a time. The tool returns a job id; poll Refresh (or edit_job_status) instead of queueing a batch.
  4. Promote deliberately. The graph is a lab graph in the editing lane. To keep a variant, promote it with bazelisk run //:manage -- promote-workflow - never copy _lab into _user.

The agent model sidecar (opt-in)

Host process, not a service

bazelisk run //:manage -- agent-model clones the pinned upstream recipe into ${AGENT_MODEL_HOME:-$HOME/qwen38-flash-next-tf} and hands the container to the recipe's own start.sh / stop.sh. It is not in docker-compose.yml, not built by docker/Dockerfile, and not a manage.sh start dependency. Bind stays 127.0.0.1 - a non-loopback HOST is refused. The 35B writing desk keeps 127.0.0.1:30000; this sidecar is 127.0.0.1:30001.

It serves nvidia/Qwen3.8-Flash-Next-FP4-Local behind an OpenAI-compatible API with tool calling and streaming, which is exactly the shape EZ_AGENT_LLM_URL expects. Point the panel at it:

Do not lower the 9 GiB reserve

MEM_FLOOR_GIB=9 is what keeps the unified-memory box from wedging under load. Every other knob above is fair game; that one is not. If the reserve cannot be honoured, the sidecar does not belong on this boot - stop it and use the 35B desk on :30000 instead (MCP and SSH tunnels).

Laptop-local MCP tools

The agent can call tools that live on your laptop, not the Spark. You add endpoints in the panel; it speaks MCP from the browser over Streamable HTTP (initialize, tools/list, tools/call), publishes each discovered tool to the agent as local__<server_id>__<tool>, and relays the call back when the agent uses it (Relay local tools).

Loopback only

An endpoint URL is refused before any fetch unless the host is loopback: 127.0.0.1, localhost, or ::1. A panel row reads refused: only loopback hosts .... That is deliberate

  • this is a local studio, and the browser is the thing doing the fetching.

Stdio servers (the shape most desktop MCP apps ship) need a bridge, and the bridge belongs on the laptop, between the browser and the server - never on the Spark. Any package that exposes an MCP stdio server as Streamable HTTP on a loopback port works; the panel does not care which one. The pattern:

Two rules keep discovery working:

  • Bind the bridge to loopback. A bridge listening on a LAN address is refused by the panel's guard, and a bridge bound to 0.0.0.0 is an open MCP server.
  • Serve Streamable HTTP, and answer CORS for the ComfyUI origin. Plain SSE-only or WebSocket-only transports will not connect from the browser, and a bridge that omits Access-Control-Allow-Origin for http://127.0.0.1:${COMFY_PORT} fails at initialize.

Discovery and tool calls never leave the laptop's loopback interface; only the tool names and the call arguments travel to the Spark.

Do not launch ComfyUI from a third-party editor

Vlo's Launch ComfyUI button (and any equivalent in another editor) is for a folder install that editor created itself. This stack owns the container lifecycle - restart: "no", the heavy confirm, the headroom preflight - so a second ComfyUI means two heavy GPU jobs and a refused start. Start ComfyUI with ./scripts/manage.sh start only, and keep weights on ./scripts/manage.sh download-models. Same rule, full wording: Vlo video editor and Host sidecars overview.
