${COMFY_OUTPUT_DIR}/guides/<slug>/<shot_id>/

TRELLIS.2 chain

All five 3d/* graphs are lane 3d, occupancy trellis - one heavy 3D job at a time. What each one consumes and where the .glb lands is the table above; how the mesh is built is this:

FactDetail
ChainTrellis2Conditioning -> structure -> shape -> upsample -> texture -> PaintMesh -> MeshToFile3D -> SaveGLB
UpsampleTrellis2UpsampleStage takes an INT target_resolution. Legal range is 1024 to 2048, step 128; default 1024. There is no 512 and no 256 - a "512 upsample" note is stale
SaveSaveGLB is the node that puts the .glb on disk, under the output prefix named above. MeshToFile3D has no widgets and writes nothing, and it keeps only batch item 0 - so 3d/prop-variants feeds SaveGLB the PaintMesh MESH directly and writes all four candidates, while the single-mesh graphs convert through it in memory
Blockout3d/blockout-mesh stops after the shape stage - no upsample, no texture VAE, no PaintMesh - so it returns an untextured gray box. Queue it for layout, then re-run the full chain on the take you keep
Variants3d/prop-variants sets EmptyTrellis2LatentStructure batch_size=4, so four candidates come off one Klein still in a single occupancy session
