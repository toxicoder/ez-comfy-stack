# Set up this computer

**What's on this page**

- **What you end up with** - a working `ssh ez-spark` and a forwarded ComfyUI port
- **What the laptop needs** - git, OpenSSH, and python3, nothing else
- **Run one command** - `manage.sh setup-client` on macOS, Linux, WSL, or Windows
- **Forward the port after the Spark is up** - the foreground tunnel and its URL
- **Related** - the full walkthrough and the one-command install

**What this enables**

- **Reaching** the studio at `http://127.0.0.1:${COMFY_PORT}` once the Spark has started
- **Skipping** copy-paste `ssh -L` flags once the `Host ez-spark` block exists
- **Keeping** the GPU job on the Spark - nothing here runs Comfy on the laptop

**Who this is for:** you, on a Mac, a Linux laptop, or a Windows PC, before anything works on the Spark. This page does **not** install Docker on the Spark, download weights, or start the stack. Compose keeps `restart: "no"` and you still type **yes** on `start` on the Spark.

Run this page first when you drive the Spark over SSH. Once the Spark is set up, continue on [Getting Started](../getting-started.md), or let one command do both machines with [One-command onboard](onboard.md).

---

## What you end up with

| Goal | Detail |
| --- | --- |
| **SSH** | `ssh ez-spark` works |
| **Forward** | `LocalForward ${COMFY_PORT} 127.0.0.1:${COMFY_PORT}` in `~/.ssh/config` |
| **Next** | On the Spark, `./scripts/manage.sh start` (type **yes**), then open `http://127.0.0.1:${COMFY_PORT}` |

Fill the Spark IP, user, and port in the **Your Spark** panel at the top of any docs page, or export them in your shell:

```bash
export SPARK_HOST="${SPARK_HOST:-127.0.0.1}"
export SPARK_USER="${SPARK_USER:-$USER}"
export COMFY_PORT="${COMFY_PORT:-8188}"
```

## What the laptop needs

- [ ] **git**, **OpenSSH client**, **python3** - `setup-client` installs what is missing
- [ ] **Homebrew** on macOS, or **apt** / **dnf** on Linux and WSL, for those installs
- [ ] **WSL2 Ubuntu** on Windows - the supported path, because `manage.sh` is bash

No Docker, no CUDA, and no weights on the laptop. The GPU job stays on the Spark.

---

## Run one command

<EzCommand id="setup-client" />

`setup-client` will:

1. Detect macOS, Linux, WSL, or Windows
2. Install git / OpenSSH / python3 when missing (Homebrew, apt, or dnf)
3. Create `~/.ssh/id_ed25519` when missing
4. Write a replaceable `Host ez-spark` block (does not wipe the rest of `~/.ssh/config`)

Then:

```bash
ssh ez-spark
```

Windows: run `scripts/utilities/setup-client.ps1`. The supported path is **WSL2 Ubuntu** (bash `manage.sh`). Without WSL, install Git for Windows + OpenSSH and use the printed `ssh -L` line.

That is a foreground tunnel. Leave it open while you use the UI. Opt-in always-on tunnel services (`launchd` / systemd) are not the default - an always-on LocalForward is easy to forget.

The one-off form of the same tunnel, for a machine where you did not write the Host block, is step 6 of [Getting Started](../getting-started.md). Tunnel and MCP notes: [MCP and SSH tunnels](../operate/mcp.md).

**Fail:** SSH refused or the wrong user -> [Host and Docker](../operate/troubleshooting-host-docker.md).
