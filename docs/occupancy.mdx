# Occupancy desk

**What's on this page**

- **Modes** - idle, blender-desk, llm-desk, klein, trellis, wan, ltx
- **Park vs stop** - `POST /free` instead of a full `start` cycle
- **The 35B writing desk** - the opt-in host sidecar and its one-time pull
- **What stays XOR** - NVENC, Cycles CUDA, LTX next to TRELLIS, llm-desk next to blender-desk
- **Occupancy state** - where `.occupancy.json` lives and what reads it
- **A desk with nobody at it** - how an orphaned record releases the Queue instead of blocking it

**What this enables**

- **Dumping** host Blender clay without typing **yes** on a full `start` cycle every time
- **Running** an opt-in 35B writing desk (`llm-desk`) while Comfy weights are parked
- **Queuing** a later TRELLIS (`3d/trellis2`) or LTX take after Blender or the sidecar is stopped
- **Keeping** `restart: "no"`, the heavy confirm, `mem_limit: 90g`, and headroom 28 GiB unchanged

<Callout type="error" title="One heavy job">
  Parked Comfy is **not** a second denoise. `blender-desk` is Workbench / CPU after models unload. `llm-desk` is the host 35B llama-server after models unload - that sidecar **is** the GPU job. Cycles CUDA, TRELLIS, Wan, LTX, and llm-desk still XOR with each other. This does **not** weaken `restart: "no"`, headroom, or download-limit clear-on-exit.
</Callout>

**Who this is for:** operators who need the GPU for something other than a denoise, or who
want to know who holds it right now. The idea behind the rule is
[Why one heavy job](learn/occupancy.md); the mode-by-job lookup is
[Occupancy matrix](operate/occupancy-matrix.md). This page owns the procedure.

## Read who holds the GPU

```bash
bazelisk run //:manage -- occupancy status
```

**Check it worked:** the printout names the current mode, whether Comfy is parked, and the
tracked PIDs. State lives at `${COMFY_OUTPUT_DIR}/.occupancy.json` (outputs, never
`${MODELS_DIR}`). The in-canvas **Occupancy gate** (`EZDCCOccupancyGate`) reads that file
only - it does not start Compose or spawn Blender.

### A desk with nobody at it

A `blender-desk` or `llm-desk` record is a GPU claim only while its sidecar process is
running. A sidecar killed outright, or a host reboot, can leave the record behind claiming
a desk that is empty, and every heavy graph then refuses at Queue and tells you to stop a
Blender that is not running.

The gate checks the recorded PIDs before it refuses, so an empty desk releases the Queue and
prints one line to the ComfyUI log instead:

```text
[ez_dcc occupancy] occupancy blender-desk has no live sidecar (pids blender_pid=0,
mcp_pid=0); released for this Queue
```

The record itself has an explicit verb:

```bash
bazelisk run //:manage -- occupancy reconcile
```

Reconcile zeroes the dead PIDs and keeps the mode, so the record still says which desk was
left dangling. A **live** sidecar still blocks: the gate never releases a Queue next to a
Workbench session or a running 35B. The verdict comes from the host, which is where
`kill -0` can actually see the sidecar - the Compose container shares no PID namespace, so a
record written before the `pids_alive` field existed stays fail-closed until the next host
verb restamps it.

## Enter a mode

| Mode | Compose | Comfy weights | 35B sidecar | GPU job |
| --- | --- | --- | --- | --- |
| `idle` | down | - | **stopped** | none |
| `blender-desk` | up **or** down | `POST /free` unload when up | **stopped** | Workbench / CPU dumps |
| `llm-desk` | up **or** down | `POST /free` unload when up | **running** (`127.0.0.1:30000`) | host llama-server GGUF |
| `klein` | up, 90g/80g | Klein 4B | **stopped** | stills |
| `trellis` | up, 90g/80g | TRELLIS.2 INT8 | **stopped** | image->mesh |
| `wan` / `ltx` | up, 90g/80g | video | **stopped** | Wan 5s / LTX App 8s |

App occupancy keys (`none` / `llm` / `klein` / ...) on Prompt Forge and research-chat are
**graph labels**. `llm` means nothing GPU. It is not `occupancy enter llm`. Mode x legal GPU
jobs: [Occupancy matrix](operate/occupancy-matrix.md).

```bash
bazelisk run //:manage -- blender-install   # once; occupancy does not install Blender
bazelisk run //:manage -- occupancy enter blender-desk
bazelisk run //:manage -- blender -- --background
bazelisk run //:manage -- occupancy enter llm-desk --yes
# OpenAI-compatible: http://127.0.0.1:30000/v1
bazelisk run //:manage -- occupancy enter trellis --yes
```

`occupancy enter` **does not** start Compose. Heavy modes tell you to
`bazelisk run //:manage -- start` (type **yes**) when the container is down.

**Check it worked:** `bazelisk run //:manage -- occupancy status` reports the mode you entered, and
the heavy mode's own message confirms the weights for that job are the only ones loaded.

### Start the 35B writing desk

One-time pull (throttled; **not** `download-models`):

```bash
bazelisk run //:manage -- download-llm --tier qwen36-35b-a3b
```

Host `llama-server` must be on `PATH` (aarch64). A missing binary prints a host-install hint
and exits 1 - do not apt/pip inside Docker. vLLM + `nvidia/Qwen3.6-35B-A3B-NVFP4` is an
operator alternative only (not wired). Reach it from a laptop with
`ssh -L 30000:127.0.0.1:30000` ([MCP and SSH tunnels](operate/mcp.md)).

**Check it worked:** `http://127.0.0.1:30000/v1` answers and `occupancy status` shows
`llm-desk` with the sidecar running.

## Park instead of stopping

`stop` is the hammer: container down, volumes kept. Use it for NVENC proxies, SuperSplat, or
a wedged UI.

`occupancy enter blender-desk` keeps Compose up, waits for an empty queue, then `POST /free`
`{unload_models, free_memory}` (the Manager unload). Host Workbench dumps
(`export-guides`, `blender-stills`, `house-views`, `blender`) are allowed. NVENC still dies if
compose is up.

If `/free` fails, Workbench may still contend for unified memory - `occupancy idle` then.

**Check it worked:** the Blender dump lands under `${COMFY_OUTPUT_DIR}` and Comfy stays up,
so no **yes** and no headroom check. [Stay in Comfy after a Blender
dump](learn/comfy-first-blender.md).

## What this is not

- Not a Compose profile for Blender (Blender stays a host binary)
- Not Cycles GPU / OptiX while Compose is up
- Not lowering `mem_limit: 90g` or `min_host_free_gib: 28`
- Not two denoises (Klein + LTX, TRELLIS + LTX, Wan + TRELLIS)
- Not `occupancy enter llm` (graph label only). Use `llm-desk` for the 35B sidecar.

## MCP on the desk

In-tree MCP servers are typed-tool stdio processes: **No** `execute_code`, **no** telemetry.
Official Comfy Cloud MCP / `comfy-mcp` stay out of the image (`manage.sh start` is the launch
path). Two desk rules only:

- **blender-mcp** bpy tools need `blender-desk`; starting it maps **idle -> blender-desk**.
- **research-mcp** and **studio-mcp** are CPU GGUF; they do not refuse a GPU Comfy session
  and do not remap `idle`. Neither queues Comfy.

Tool tables, the `--call` form, and the Path D tunnels: [MCP and
SSH tunnels](operate/mcp.md).
