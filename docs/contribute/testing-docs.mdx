# Testing docs

**What's on this page**

- **Validate lanes** - one command per gate, and what each one runs
- **100% Python gate** - the packages it covers and how the GPU paths stay hermetic
- **Shell function inventory** - invoked by a test, not merely named
- **Docs build** - generators first, then the Fumadocs export, with the per-generator escape hatches
- **deploy-docs.yml** - which branch publishes which Pages alias
- **Related** - the style rules these gates enforce

**What this enables**

- **Running** the same gates CI uses before a docs PR
- **Knowing** the 100% gate is every first-party production Python module, with GPU/bpy/network branches covered by hermetic fakes
- **Publishing** versioned docs without mike or MkDocs
- **Regenerating** `docs/generated/` so the committed tree matches the generators

## Validate lanes

Makefile shims call Bazelisk when present. Canonical commands: [Building with Bazel](building-with-bazel.md).

| Lane | What it runs |
| --- | --- |
| **`bazelisk test //:test-fast`** | BATS + node:test (`tests/js/`) + Python (`pytest-xdist` when installed) + Pyright + mypy |
| **`bazelisk test //:coverage`** | Same as `//:test-fast` via Bazel, plus the kcov report |
| **`bazelisk test //:lint --test_tag_filters=manual`** | ShellCheck + shfmt + buildifier (Pyright + mypy live in `//:test-fast`) |
| **`bazelisk test //tests:typecheck`** | Pyright (Pylance) + mypy |
| **`bazelisk run //docs:docs`** | generators then Fumadocs static export (`docs-site/out/`) |
| **`bazelisk run //docs:generate`** | the four `docs/generate_*.py` generators only; no npm, no export |
| **`bazelisk run //tests:build_quality_js`** | regenerate the Quality tier JS from `presets.py` |
| **`bazelisk run //:fix`** | buildifier + `shfmt -w` |
| **`bazelisk run //:manage -- doctor`** | Host health check (not hermetic) |

Install once: `pip install -r tests/requirements.txt` and Node 22+ (`bazelisk run //docs-site:install`).

Pyright errors and mypy errors are **defects**. Do not skip the gate.

## 100% Python gate

`bazelisk test //:coverage` (`tests/run_pytest.sh` underneath) fail-under **100** on every first-party production package:

- `custom_nodes`
- `docker` (UM patches, `seed_clay_inputs`, `pythonpath/sitecustomize`)
- `docs` generators (`commands.py`, `glossary.py`, `page_brief.py`, workflow/cinema/audio/shell)
- `scripts/lib`
- `studio-ui`
- `tools` (Blender exporters; `bpy` is faked)

Vendored `custom_nodes/ez_dcc/_guide_pack.py` is included (same tests as `scripts/lib/guide_pack.py`). GPU loaders, llama.cpp, and host Blender are exercised with `sys.modules` fakes - tests stay hermetic.

`PYTHONPATH=docker:docker/pythonpath:custom_nodes:scripts/lib:studio-ui:docs:tools`.

## Shell function inventory

Every function under `scripts/**/*.sh` and `docker/**/*.sh` must be **invoked by a test** under `tests/` (strict; a comment that only names the function does not count). Entrypoint `main` is skipped. New library functions ship with BATS/pytest in the **same commit**. kcov remains optional and non-fatal.

## Docs build

```bash
bazelisk run //docs-site:install               # npm ci --legacy-peer-deps, once
bazelisk run //docs:generate                    # the four generators only, no npm, no export
bazelisk run //docs:docs                        # generators, then the Fumadocs export

# Escape hatches: one generator only, when you are iterating on that generator
python3 docs/generate_shell_docs.py
python3 docs/generate_workflow_docs.py
python3 docs/generate_cinema_docs.py
python3 docs/generate_audio_docs.py
```

`//docs:generate` is the loop you want after editing a shell function, a workflow graph, or a Cinema/Audio Rack JSON: no npm install, no webpack, and it prints the file count it wrote. `bazelisk test //tests:pytest` then fails if the committed `docs/generated/` no longer matches the generators, so regenerate and commit in the same change.
`generate_shell_docs.py` writes `docs/generated/shell/reference.md` from `# ##`, `# @command`, and `# @function` comments. `generate_workflow_docs.py` writes `docs/generated/workflows/` and `docs/reference/workflow-nodes.md` from `_lab` JSON plus `docs/workflow_nodes.py`. `generate_cinema_docs.py` writes `docs/generated/cinema/` from Cinema Rack JSON. `generate_audio_docs.py` writes `docs/generated/audio/` from Audio Rack JSON. Do not hand-edit those files. The Next export fails closed on MDX/TypeScript errors. MDX compiles on demand (`dynamic: true` in `docs-site/source.config.ts`), so webpack does not bundle the ~850-page corpus.

Pins: Fumadocs on Next.js 16 (`docs-site/package.json`). Node **22+**. [Docs style](docs-style.md).

## deploy-docs.yml

`.github/workflows/deploy-docs.yml` runs on push to **`main`** / **`development`** (docs paths) or `workflow_dispatch`.

| Git branch | Pages alias |
| --- | --- |
| **`main`** | **`latest`** (default site) |
| **`development`** | **`development`** |

PR validation is `bazelisk run //docs:docs` in CI only (no Pages push). Each run builds **one** alias and keeps the other from `origin/gh-pages`. The export is `next build --webpack` in-process with one static-generation worker and `NODE_OPTIONS=--max-old-space-size=5120` so the ~850-page site fits GitHub's 7 GB runner. CI calls `./docs/manage-docs.sh build` after `bazelisk shutdown` so Bazel is not resident during the compile. Publish uses `scripts/ci/publish-pages-tree.sh` (a separate git worktree) so Next's rewrite of tracked `docs-site/next-env.d.ts` cannot block the `gh-pages` checkout. The helper refuses any file at GitHub's 100 MiB blob limit. Generated encyclopedias are indexed by title, headings, and tags only so the static `/api/search` export stays under that cap. Deploy sets `EZ_DOCS_PUBLISHED_AT` for the last-published chip. `docs-site/lib/site.ts` stamps `__DOCS_GIT_REF__` and GitHub blob/tree URLs to the long-lived ref.

Public URLs: [latest](https://toxicoder.github.io/ez-comfy-stack/latest/) - [development](https://toxicoder.github.io/ez-comfy-stack/development/).
