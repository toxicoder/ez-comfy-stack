# Vlo video editor

**What's on this page**

- Vlo as a **host** browser editor (AGPL-3.0), not a Compose service
- Install and run on the Spark host (`install.sh` then `run.sh` on `127.0.0.1:6332`)
- Pointing Vlo's ComfyUI bridge at this stack's `${COMFY_PORT}`
- What this stack still owns: the container lifecycle and the model weights

**What this enables**

- Timeline editing in a browser while the AI compute stays server-side on the single Spark
- No editor code in `docker/Dockerfile`, no ComfyUI node, no `manage.sh` verb
- An in-browser alternative to the Kdenlive / Shotcut OTIO file handoff

<Callout type="warning" title="Host app, not a service">
  Vlo (`PxTicks/vlo`, **AGPL-3.0**) is a host-side app you install and run yourself. It is **not** a Compose service, **not** a ComfyUI custom node, **not** cloned into the Comfy image, and **not** a `manage.sh` verb. It brings its own Node.js + Python backend on the host, keeps projects on the host disk, and edits in a Chromium-based browser. Every generation is a normal ComfyUI Queue on the Spark.
</Callout>

## Why Vlo

Vlo drives the existing ComfyUI over its live bridge, so the timeline is local and cheap; each denoise is one Queue on the Spark. The AGPL app stays outside the MIT tree and outside the image, and the one-heavy-GPU-job rule is untouched. For a file handoff instead of a live bridge, use the OTIO export into Kdenlive / Shotcut: [Studio sidecars](studio-sidecars.md).

## Requirements

- A **Chromium-based browser** (Chrome, Edge; Opera may work). Firefox and Safari are not supported: the editor needs the File System Access API and WebCodecs, and its media renderer wraps mediabunny
- `git` on the host. That is the only prerequisite - the installer fetches Node.js, Python, and uv when they are missing
- ComfyUI from this stack, already up: `./scripts/manage.sh start`

## Install (host)

```bash
git clone https://github.com/PxTicks/vlo
cd vlo
./install.sh        # Windows: install.bat
./run.sh            # Windows: run.bat; opens http://127.0.0.1:6332
```

`run.sh` accepts `--no-browser`, `--host=`, and `--port=`. From a laptop, forward the ComfyUI port as usual and open the editor on `127.0.0.1`:

```bash
ssh -L "${COMFY_PORT}:127.0.0.1:${COMFY_PORT}" "${SPARK_USER}@${SPARK_HOST}"
```

## Point the bridge at this stack

Vlo expects ComfyUI at `http://127.0.0.1:8188` by default. Change it in **App settings -> Runtime settings**.

| What you publish | ComfyUI URL in Vlo |
| --- | --- |
| `COMFY_PORT=8188` (default) | `http://127.0.0.1:8188` |
| any other `COMFY_PORT` | `http://127.0.0.1:${COMFY_PORT}` |

`backend/.env` also reads `COMFYUI_URL`. Once you change the value in the app, **the app setting wins** - edit it in one place.

First launch asks how to use ComfyUI: **Install ComfyUI**, **Choose ComfyUI folder**, or skip and set it later in **App settings -> Runtime settings**. Skip it (or set the URL straight away). This stack owns the ComfyUI install inside the container, so there is no folder for Vlo to choose.

## Operator path

```bash
./scripts/manage.sh start     # type yes; ComfyUI on ${COMFY_PORT}
cd vlo && ./run.sh            # editor on http://127.0.0.1:6332
# then: App settings -> Runtime settings -> http://127.0.0.1:${COMFY_PORT}
```

Edit on the timeline. Every generation lands as a Queue in ComfyUI at `${COMFY_PORT}` - watch it in the Comfy tab or with `./scripts/manage.sh logs`.

## What this stack owns

<Callout type="error" title="Do not launch ComfyUI from Vlo">
  Start ComfyUI with `./scripts/manage.sh start`. Do **not** use Vlo's **Launch ComfyUI** button - it is for a folder install Vlo created itself. A second ComfyUI on the Spark means two heavy GPU jobs and a headroom refuse. [Occupancy desk](occupancy.md).
</Callout>

| Vlo feature | Use it here? | Why |
| --- | --- | --- |
| **Launch ComfyUI** | **No** | `./scripts/manage.sh start` owns the container lifecycle (`restart: "no"`, heavy confirm, headroom preflight) |
| Vlo model downloads | **No** | Weights stay on `./scripts/manage.sh download-models`. That feature assumes a local `COMFYUI_INSTALL_DIR` folder plus a local ComfyUI URL, which the containerized stack does not expose |
| Timeline, edit, export | **Yes** | Host CPU + browser (WebCodecs). Stop Comfy first if the encode will use the GPU |
| ComfyUI bridge (Queue) | **Yes** | The whole point: heavy AI compute stays server-side on the Spark |
